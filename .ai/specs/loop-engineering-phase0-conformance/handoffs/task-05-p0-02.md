## Important Decisions

- Gate commands receive writable root `.` only inside a disposable checkout, while
  `test/golden` remains protected; no gate command writes the authoritative worktree.
- Every command check starts from the same `git write-tree` hash. A retry stays in
  that check's disposable workspace so a genuine fail-then-pass can be observed.
- `git worktree add` disables repository hooks to prevent target-controlled hook
  execution before the sandboxed boundary.
- The runner kills the detached child process group on timeout or output ceiling,
  and caps captured output at 1 MiB.
- Existing governed package-install network semantics were preserved; no dependency
  or new policy surface was introduced.
- Recovery determines terminality relative to the latest intent sequence and records
  the originating role, preventing a rejected retry from inheriting broader authority;
  a rejected replay rolls back again so partial allowed writes cannot remain.

## Review

ตรวจ correctness และ security ตาม repository review protocols แล้ว พบหนึ่ง actionable
finding: recovery replay ที่เขียน allowed path ก่อนถูก sandbox reject อาจเหลือ partial
write อยู่ เพิ่ม discriminating RED test แล้วแก้ด้วย rollback ซ้ำหลัง rejection จน GREEN
ไม่เหลือ unresolved actionable finding การแก้เชิง hardening อื่นครอบคลุม bounded output,
whole-process-group termination, disabled checkout hooks และ recovery event ordering

Residual ที่ยอมรับตาม design:

- non-darwin ไม่มี enforcing backend จึง fail closed แทนการรัน unsandboxed
- disposable worktree cleanup เป็น best-effort หลัง authoritative result แล้ว; temp path
  ไม่มี durable authority และ original artifact ไม่ถูกแก้
- ข้อความ denial จาก OS ใช้จัดหมวด structured rejection แบบ conservative ซึ่งอาจ
  fail safe ต่อข้อความ `Permission denied` ที่ child พิมพ์เอง แต่ไม่ทำให้ authority กว้างขึ้น
