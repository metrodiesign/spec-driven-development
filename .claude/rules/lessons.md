# Lessons (promoted from retrospectives)

> Add ONLY genuinely reusable, mistake-preventing lessons here. Prune stale ones.
> The full record lives in `retrospectives/`. Keep this file lean (see §10 of the guide).

- **Pattern**: pure-logic-first — แยก logic ที่ทดสอบได้ (เช่น สูตรคำนวณ/validation) ออกเป็น pure function ใน `lib/` แล้วเขียน unit test ให้เขียวก่อนแตะ UI. — **Why**: ความถูกต้องไม่ปนกับ rendering, ปิด acceptance ที่เป็นตัวเลขได้ก่อน wire UI.
- **Pattern**: ตอนตรวจ interaction ผ่าน browser_evaluate กับ React controlled component ให้แยก "action (click/dispatch)" กับ "read DOM" เป็นคนละ evaluate call. — **Why**: React re-render เป็น async; อ่านใน call เดียวกับ click จะได้ค่าเก่า (race) → เกือบรายงานว่า UI พังทั้งที่ logic ถูก.
- **Pattern**: /spec-analyze ก่อน design คุ้มเสมอสำหรับฟีเจอร์ที่มี logic — มันจับ conflict/gap ที่ทำให้ test เขียนไม่ได้ (หน่วย/วิธีปัดเศษของผลลัพธ์, trigger คำนวณ, empty state, conflict รูป-ต้องมีเน็ต-vs-ห้าม broken). — **Why**: แก้ที่ requirements ถูกกว่าแก้โค้ดทีหลัง.
- **Pattern**: verify output ที่ tooling แปลงชื่อ (next/font, CSS-module) ด้วย artifact จริง (grep `<html>` tag เห็น hashed class) ไม่ใช่ grep literal ชื่อที่ตั้งเอง. — **Why**: ชื่อถูก hash → grep literal ไม่เจอ → เกือบรายงาน false-negative ว่าฟอนต์ไม่โหลด.
- **Pattern**: audit vuln ที่เป็น transitive ใน core framework เอง (เช่น postcss ที่ next bundle) → flag + ระบุเงื่อนไข resolve, ห้าม `npm audit fix --force`. — **Why**: fix --force downgrade core dep เป็น breaking (next→9.x) เลวกว่าตัว vuln; ต้องรอ upstream bump.
- **Pattern**: เมื่อ data type อ้าง type ที่ task ก่อนหน้าเป็นเจ้าของ (เช่น `Service.icon: IconName` จาก Icon registry) ให้ import มา constrain แทน re-declare/เดาชื่อ — `tsc --noEmit` จะพิสูจน์ integrity ข้ามโมดูลให้ฟรี และกัน value ที่ render เป็นกล่องว่าง/ไอคอนหาย. — **Why**: typo ชื่อ icon/enum จะ compile-fail ทันทีแทนพังตอน render ทีหลัง; data-only task verify ด้วย `tsc` เป็น gate จริง (count เป็นรอง).
- **Pattern**: design.md ที่มีตาราง factor + ตัวอย่างยืนยันตัวเลข → คำนวณ expected ทุกแถวด้วยมือใส่ test table (รวม 1 ค่าที่ปัดเศษไม่ลงตัวเพื่อพิสูจน์ `Math.round`), อย่าใช้ snapshot. — **Why**: snapshot รับค่าผิดเงียบๆ; ค่าที่คำนวณมือ fail ทันทีถ้าสูตรเพี้ยน → test เป็น executable spec. Export ค่าขอบ (`AGE_MIN/MAX`...) ให้ boundary test reuse แทน hardcode ซ้ำ source of truth.
- **Pattern**: browser-verify interaction ในโปรเจกต์นี้ใช้ production build เสมอ — `npm run build` + `PORT=<free> npx next start` แล้วชี้ Playwright ไป `http://127.0.0.1:<port>/` (เลข IPv4 ไม่ใช่ `localhost`). ก่อนเชื่อผลคลิกใดๆ probe hydration (`__reactFiber$`/`__reactProps$` มีบน element); ถ้าไม่มี = ยังไม่ hydrate = คลิกเป็น no-op (ไม่ใช่บั๊ก UI). หลังแก้โค้ดทุกครั้ง **rebuild** ก่อนเทสซ้ำ. — **Why**: `next dev` ที่นี่ HMR ws ถูก proxy พัง → page โหลดแต่ React ไม่ hydrate → false-negative; `curl -sf ... 200` / build เขียว พิสูจน์แค่ "มีอะไรรันอยู่" ไม่ใช่ "โค้ดล่าสุดของเรา" (เคยมี app อื่นจอง :3000 + serve stale `.next`).
- **Pattern**: วัด horizontal overflow ด้วย `document.documentElement.scrollWidth > innerWidth` เป็น primary test เสมอ; ค่อยใช้ `getBoundingClientRect().right > innerWidth` ระบุ culprit _หลัง_ ยืนยันว่ามี scroll จริง และ **ตัด svg/rect/circle/path/g ออก** (SVG ที่ `preserveAspectRatio="slice"` รายงาน box เกิน viewport เสมอแม้ parent `overflow-hidden` ครอบ = false positive). ถ้า culprit เป็น component ของ task อื่น = รายงาน อย่าแก้เงียบ (ยกเว้น task ที่เป็น page-wide audit เอง เช่น responsive/a11y pass — ตัวมัน own REQ overflow ทั้งหน้า แก้ได้). culprit probe ให้ **ตัด ancestor ที่ clip ออกด้วย** (เดิน parent หา `overflow-x: hidden/clip/auto/scroll` → ถ้าเจอ = ignore) รายงานเฉพาะ node ที่ "unclipped" เท่านั้น — slider/carousel ที่ตั้งใจเลื่อนจะมี `.right` โตมาก (เช่น 2139px) แต่ถูก clip โดย container = ไม่ทำให้ document overflow จริง. — **Why**: bounding box เดี่ยวไม่ใช่เครื่องมือวัด overflow (false positive จาก SVG geometry + slider ที่ clip แล้ว ทำให้เกือบไล่แก้ผิดที่); overflow ไม่บอกที่มา เดาแล้วแก้ผิดไฟล์ = scope creep + พัง task boundary (เคสซ้ำ: overflow 768 เป็นของ UtilityBar task 4 ไม่ใช่ section task 5/6).
- **Pattern**: Tailwind `md:` = `min-width:768px` **รวม 768 ด้วย** → element ที่ตั้งใจ "ซ่อน ≤768px" ด้วย `hidden md:flex` จะ _โผล่_ ที่ 768 พอดี (off-by-one) → ชน element อื่น = overflow ที่ viewport ขอบพอดี. ต้องการซ่อนถึง 768 จริงให้ใช้ `lg:` (≥1024) หรือ `max-md:hidden`. — **Why**: breakpoint inclusive ทำให้ "≤768" กับ "md:" คนละความหมาย; bug class นี้โผล่เฉพาะที่ค่า breakpoint พอดี (ดูปกติที่ 375/1440) จับได้เฉพาะตอน audit ที่ 768 ตรงๆ.
- **Pattern**: รัน long-running server (`next start`) ในโปรเจกต์นี้ผ่าน `rtk proxy npx next start` เพื่อเห็น raw log ("Ready"/error). — **Why**: rtk hook rewrite output เป็น summary ("Errors: 1 | Warnings: 0") บดบัง log จริง → เข้าใจผิดว่า server พังทั้งที่ขึ้น 200.
- **Pattern**: dropdown/menu ให้ open-only — เปิดด้วย hover/focus/click, ปิดด้วย mouseleave/ESC/click-outside เท่านั้น; อย่าให้ `onClick` เป็น toggle เมื่อมี `onMouseEnter`/`onFocus` เปิดอยู่แล้ว. — **Why**: hover/focus เปิด → click toggle ปิดทันที (pointer click ฟัง mouseenter ก่อน) → เมนูไม่เปิดเลย; ยังครบ REQ hover/focus + ESC.
- **Pattern**: filter/grid เก็บ logic เป็น pure fn ใน `lib/` (`filter*(items, ...args)` ไม่มี global) → state แต่ละ section อิสระเพราะเป็น argument ล้วน, unit test ครอบ filter/search/empty ได้ก่อนแตะ UI. เมื่อ chip filter จะ map 1:1 กับ entity (เช่นการ์ด = ประเภทเอง → กรองเหลือใบเดียว ไร้ค่า) ให้จัด taxonomy เหนือ entity และยืนยัน completeness ด้วย test (union ของกลุ่ม = ครบทุก entity). — **Why**: ปิด REQ filter/empty ระดับ logic ก่อน wire UI (เหมือน premium); taxonomy ทำให้ filter มีความหมาย UX จริงแทนทำตาม spec ตรงตัวจนได้ผลไร้ประโยชน์ — แจ้ง user เป็น assumption เมื่อ taxonomy ไม่ได้มาจาก data.
- **Pattern**: form ที่มี pure validation lib อยู่แล้ว (เช่น calculator → `lib/premium.ts`) ให้ UI เก็บ raw `string` state จาก `input` แล้ว parse → `null|number` ตอนคำนวณ แล้วโยนเข้า lib — อย่า duplicate กฎ validation (empty/NaN/นอกช่วง) ใน component; import boundary constants (`AGE_MIN/MAX`...) มาโชว์ใน label/`min`/`max` แทน hardcode. trigger คำนวณที่ submit + blur ฟิลด์สุดท้ายเท่านั้น (ไม่ทุก keystroke) กัน error กระพริบ. — **Why**: validation 2 ที่จะ drift; lib เป็น single source ปิด acceptance ได้ก่อน wire UI, UI แค่ orchestrate. browser-verify ค่าตัวเลข (12,000) ต้องแยก action-call (set+submit) กับ read-call ตาม React async re-render.
- **Pattern**: ก่อนใส่สี/สไตล์ state ใหม่ใน component (error/danger/success) grep token ใน `tailwind.config.ts` ก่อน; ไม่มี = เพิ่ม semantic token ที่ config ที่เดียว แล้วเรียกผ่าน utility (`text-danger`) — อย่า hardcode hex ดิบ และอย่าใช้ Tailwind default palette (`text-red-600`) ที่เลี่ยง raw hex แต่ก็ไม่ใช่ token ของโปรเจกต์. flag ให้ a11y pass ตรวจ contrast ของ token ใหม่. — **Why**: design token เป็น single source (anti-pattern ห้าม hardcode สีดิบ); เพิ่ม token ถูกกว่าตามแก้ค่าซ้ำทีหลัง.
- **Pattern**: per-task/session cost จริงดึงจาก `.cost.total_cost_usd` (payload statusLine ของ Claude Code) เท่านั้น — เก็บผ่าน ledger ที่ `statusline.sh` เขียนต่อ session, และ skill อ่านเองได้ผ่าน env `$CLAUDE_CODE_SESSION_ID`. อย่าคูณ token จาก transcript: overcount 1.6-3.7x แม้ dedup (พิสูจน์: task4 transcript $19.80 vs จริง $5.36). subscription ไม่คิดเงินจริง $ เป็น estimate; headless `/cost` โชว์แค่ "subscription". — **Why**: ระบบคำนวณ cost ให้แล้วผ่าน statusline; recompute เองได้เลขผิดเสมอ. ledger ต้องมีก่อน session เริ่ม (session ปิดแล้ว resume reset cost=0 กู้ไม่ได้).
- **Pattern**: headless `claude -p` buffer output จนงานจบ — pane ว่าง/CPU ต่ำ ≠ ค้าง. ก่อนฆ่า ตรวจ progress บน disk (`git status`, ไฟล์ใหม่, node_modules) ไม่ใช่ดู pane. และ `--permission-mode acceptEdits` ครอบแค่ Edit ไม่ครอบ Bash → npm/scaffold ติด permission เงียบใน headless (ต้อง `--dangerously-skip-permissions` หรือ `--allowedTools`). — **Why**: เคยฆ่า scaffold ที่กำลังทำงานเพราะ pane ว่าง.
- **Pattern**: หลัง command fail ให้อ่าน output ให้จบก่อนยิงใหม่; แก้ script แล้ว **Read กลับยืนยันการแก้ (โดยเฉพาะ `cd`/path)** ก่อนรัน. error เดิมซ้ำ 2 ครั้ง = หยุด. — **Why**: ลืม `cd` ใน resume-pane ซ้ำ 4 รอบเพราะ re-fire background blind ไม่อ่านผลรอบก่อน + ประกาศ "แก้แล้ว" โดยไม่ได้แก้บรรทัดจริง.
- **Pattern**: section interactive ใหม่ที่ต้องเคารพ `prefers-reduced-motion` (slider/carousel/animation) ใช้ CSS transition ปกติได้เลย — `globals.css` มี media query ครอบ `transition-duration`/`animation` ทั้งหน้าแล้ว ไม่ต้องเขียน `useReducedMotion` hook ต่อ component. slider index แยกเป็น pure fn (`nextSlide/prevSlide` wrap ด้วย modulo) ใน `lib/` → test wrap-around ใน node env ได้ (vitest `environment:node`, include `lib/` เท่านั้น) ก่อนแตะ UI. — **Why**: ได้ REQ-16.5 ฟรีไม่เพิ่ม JS; index math ที่ test แล้วแยกจาก DOM กัน off-by-one/ไม่ wrap โดยไม่ต้อง jsdom.
