# Lessons (promoted from retrospectives)

> Add ONLY genuinely reusable, mistake-preventing lessons here. Prune stale ones.
> The full record lives in `retrospectives/`. Keep this file lean (see §10 of the guide).

- **Pattern**: pure-logic-first — แยก logic ที่ทดสอบได้ (เช่น สูตรคำนวณ/validation) ออกเป็น pure function ใน `lib/` แล้วเขียน unit test ให้เขียวก่อนแตะ UI. — **Why**: ความถูกต้องไม่ปนกับ rendering, ปิด acceptance ที่เป็นตัวเลขได้ก่อน wire UI.
- **Pattern**: ตอนตรวจ interaction ผ่าน browser_evaluate กับ React controlled component ให้แยก "action (click/dispatch)" กับ "read DOM" เป็นคนละ evaluate call. — **Why**: React re-render เป็น async; อ่านใน call เดียวกับ click จะได้ค่าเก่า (race) → เกือบรายงานว่า UI พังทั้งที่ logic ถูก.
- **Pattern**: /spec-analyze ก่อน design คุ้มเสมอสำหรับฟีเจอร์ที่มี logic — มันจับ conflict/gap ที่ทำให้ test เขียนไม่ได้ (หน่วย/วิธีปัดเศษของผลลัพธ์, trigger คำนวณ, empty state, conflict รูป-ต้องมีเน็ต-vs-ห้าม broken). — **Why**: แก้ที่ requirements ถูกกว่าแก้โค้ดทีหลัง.
- **Pattern**: verify output ที่ tooling แปลงชื่อ (next/font, CSS-module) ด้วย artifact จริง (grep `<html>` tag เห็น hashed class) ไม่ใช่ grep literal ชื่อที่ตั้งเอง. — **Why**: ชื่อถูก hash → grep literal ไม่เจอ → เกือบรายงาน false-negative ว่าฟอนต์ไม่โหลด.
- **Pattern**: audit vuln ที่เป็น transitive ใน core framework เอง (เช่น postcss ที่ next bundle) → flag + ระบุเงื่อนไข resolve, ห้าม `npm audit fix --force`. — **Why**: fix --force downgrade core dep เป็น breaking (next→9.x) เลวกว่าตัว vuln; ต้องรอ upstream bump.
- **Pattern**: เมื่อ data type อ้าง type ที่ task ก่อนหน้าเป็นเจ้าของ (เช่น `Service.icon: IconName` จาก Icon registry) ให้ import มา constrain แทน re-declare/เดาชื่อ — `tsc --noEmit` จะพิสูจน์ integrity ข้ามโมดูลให้ฟรี และกัน value ที่ render เป็นกล่องว่าง/ไอคอนหาย. — **Why**: typo ชื่อ icon/enum จะ compile-fail ทันทีแทนพังตอน render ทีหลัง; data-only task verify ด้วย `tsc` เป็น gate จริง (count เป็นรอง).
- **Pattern**: design.md ที่มีตาราง factor + ตัวอย่างยืนยันตัวเลข → คำนวณ expected ทุกแถวด้วยมือใส่ test table (รวม 1 ค่าที่ปัดเศษไม่ลงตัวเพื่อพิสูจน์ `Math.round`), อย่าใช้ snapshot. — **Why**: snapshot รับค่าผิดเงียบๆ; ค่าที่คำนวณมือ fail ทันทีถ้าสูตรเพี้ยน → test เป็น executable spec. Export ค่าขอบ (`AGE_MIN/MAX`...) ให้ boundary test reuse แทน hardcode ซ้ำ source of truth.
- **Pattern**: browser-verify interaction ในโปรเจกต์นี้ใช้ production build เสมอ — `npm run build` + `PORT=<free> npx next start` แล้วชี้ Playwright ไป `http://127.0.0.1:<port>/` (เลข IPv4 ไม่ใช่ `localhost`). ก่อนเชื่อผลคลิกใดๆ probe hydration (`__reactFiber$`/`__reactProps$` มีบน element); ถ้าไม่มี = ยังไม่ hydrate = คลิกเป็น no-op (ไม่ใช่บั๊ก UI). หลังแก้โค้ดทุกครั้ง **rebuild** ก่อนเทสซ้ำ. — **Why**: `next dev` ที่นี่ HMR ws ถูก proxy พัง → page โหลดแต่ React ไม่ hydrate → false-negative; `curl -sf ... 200` / build เขียว พิสูจน์แค่ "มีอะไรรันอยู่" ไม่ใช่ "โค้ดล่าสุดของเรา" (เคยมี app อื่นจอง :3000 + serve stale `.next`).
- **Pattern**: verify เจอ overflow/บั๊กที่ "ไม่ใช่ไฟล์ที่เพิ่งแก้" → query element ที่ `getBoundingClientRect().right > innerWidth` ระบุ culprit ด้วยตำแหน่งจริงก่อนแก้; ถ้าเป็น component ของ task อื่น = รายงาน อย่าแก้เงียบ. — **Why**: overflow ไม่บอกที่มา; เดาแล้วแก้ผิดไฟล์ = scope creep + พัง task boundary (เคสนี้ overflow 768 เป็นของ UtilityBar task 4 ไม่ใช่ section task 5).
- **Pattern**: รัน long-running server (`next start`) ในโปรเจกต์นี้ผ่าน `rtk proxy npx next start` เพื่อเห็น raw log ("Ready"/error). — **Why**: rtk hook rewrite output เป็น summary ("Errors: 1 | Warnings: 0") บดบัง log จริง → เข้าใจผิดว่า server พังทั้งที่ขึ้น 200.
- **Pattern**: dropdown/menu ให้ open-only — เปิดด้วย hover/focus/click, ปิดด้วย mouseleave/ESC/click-outside เท่านั้น; อย่าให้ `onClick` เป็น toggle เมื่อมี `onMouseEnter`/`onFocus` เปิดอยู่แล้ว. — **Why**: hover/focus เปิด → click toggle ปิดทันที (pointer click ฟัง mouseenter ก่อน) → เมนูไม่เปิดเลย; ยังครบ REQ hover/focus + ESC.
