# Stack lessons — Next.js / React / Tailwind / Playwright / vitest

> Path-scoped: loads only when Claude reads a matching file (app/**, *.ts(x), *.css,
> *.config.*). Stack/UI-specific lessons promoted from retrospectives; universal process
> lessons live in `lessons.md` (always-on). Keep lean, prune stale.

- **Pattern**: pure fn ที่ task มาก่อน `data/` ในลำดับ dependency (data depends filters) ห้าม import concrete data type (`InsuranceType`/`Promotion`) — circular (data import `InsuranceCategory` กลับจาก filters). ใช้ generic structural constraint `<T extends {name;tagline;category}>` แทน: ตัด cycle, type-safe, คืน `T[]` เดิม, test ด้วย fixture ได้ทันทีไม่รอ data. owner ของ enum/taxonomy (`InsuranceCategory`) อยู่ที่ fn นี้ (single source) ให้ data/ import มา constrain. completeness invariant ("union ทุกหมวด=ทุก entity") ที่ spec สั่ง "ครอบโดย test ของ task ก่อน data" → test _union logic_ ด้วย fixture (ไม่ขาด/ซ้ำ/หมวดว่าง); completeness ของ data จริงปิดด้วย `tsc` ที่ task data (`category: InsuranceCategory` non-optional = compile-time guarantee ทุก entity มีหมวด). — **Why**: import data จริงใน test ของ task ก่อนหน้า compile ไม่ผ่าน (module ยังไม่มี); generic + แยก "logic invariant (fixture, now)" จาก "data integrity (tsc, later)" ปิดทั้งคู่โดยไม่ฝืนลำดับ dependency.
- **Pattern**: Icon registry type-safe ใช้ `const ICONS = {...} satisfies Record<string, ReactNode>` แล้ว `type IconName = keyof typeof ICONS` — ได้ literal key union (autocomplete + typo fail tsc) พร้อม value-check ในประกาศเดียว. อย่าใช้ annotation `: Record<string, ReactNode>` ตรงๆ เพราะ widen key เป็น `string` -> IconName หลวม typo ไม่ถูกจับ. — **Why**: data task ฝั่งหลัง (`Service.icon: IconName`) พึ่ง union แคบนี้กัน icon หาย/กล่องว่าง; `satisfies` คงทั้ง narrow key และ value constraint.
- **Pattern**: fallback art / decorative SVG ที่ห้าม raw hex (REQ-15.3) ทำ gradient ด้วย Tailwind utility บน wrapper div (`bg-gradient-to-br from-primary to-primary-dark`) + motif เป็น `currentColor` (`text-accent`) — ไม่ใช่ `<linearGradient><stop stop-color="#...">` ที่บังคับ hex ดิบ. varied per category = map category -> IconName ต่างกัน reuse Icon. — **Why**: SVG gradient stop รับแต่ค่าสีตรง (ไม่กิน Tailwind class); ทำ gradient ใน SVG = ละเมิด no-hardcode-hex. ย้าย gradient ขึ้น wrapper แก้ครบทั้ง varied + token-only.
- **Pattern**: page-wide audit task (responsive/a11y/visual) own เกณฑ์ระดับ "ทั้งหน้า" ที่ไม่มี section task ไหน own — `<h1>` ต้องมีเป๊ะ 1 ตัวทั้งหน้า. probe `document.querySelectorAll('h1').length` ทุกครั้ง: section แยกทำมักใช้ `h2` หมด -> ทั้งหน้า h1=0 (ผิด semantic) แม้ทุก task ย่อย "ผ่าน" ในขอบเขตตัวเอง. แก้: promote headline หลัก (hero style `text-h1` อยู่แล้ว) เป็น `<h1>` เปลี่ยนแค่ tag — h1 ไม่ต้อง DOM-first. — **Why**: ไม่มีใคร own h1 ระดับหน้านอกจาก pass สุดท้าย; defect ที่ section-by-section มองข้ามเสมอ.
- **Pattern**: browser-verify ที่ viewport boundary (เช่น 768 ที่ `lg:`/`md:` toggle) ต้องชดเชย scrollbar — Playwright `setViewportSize(768)` ได้ `clientWidth` ~753 (scrollbar กิน ~15px) -> media query (eval ตาม document width ไม่รวม scrollbar) ยังไม่ toggle. ตั้ง window width = breakpoint + scrollbar (เช่น 783) ให้ `clientWidth=768` เป๊ะก่อนเชื่อผล. ยืนยัน `clientWidth` จริงทุกครั้ง อย่าเชื่อค่าที่ตั้ง. — **Why**: off-by-one breakpoint จับได้เฉพาะค่าเป๊ะ; ไม่ชดเชย scrollbar = เทสต์ที่ 753 (ปลอดภัย) พลาดบั๊กที่ 768.
- **Pattern**: a11y probe หา input "ไม่มี accessible name" เช็ก `i.labels?.length || aria-label || aria-labelledby` ตรงๆ — อย่า heuristic จาก `textContent` หรือ whitelist `type` (number/text) เพราะ `type=search`/อื่นจะหลุด list -> false positive. คุม 2 metric ขัดกัน (noName vs inputNoLabel); ขัด = probe ผิด ไม่ใช่บั๊กหน้า ตามดู `type`/`labels` จริงก่อนสรุป. — **Why**: เกือบรายงานบั๊กปลอม + ใส่ aria ซ้ำซ้อน เพราะ exclusion list ของ probe ไม่ครบ; label[for] ทำให้ input มีชื่อแม้ aria=null.
- **Pattern**: ตรวจ interaction ผ่าน browser_evaluate กับ React controlled component แยก "action (click/dispatch)" กับ "read DOM" เป็นคนละ evaluate call. — **Why**: React re-render async; อ่านใน call เดียวกับ click ได้ค่าเก่า (race) -> เกือบรายงานว่า UI พังทั้งที่ logic ถูก.
- **Pattern**: verify output ที่ tooling แปลงชื่อ (next/font, CSS-module) ด้วย artifact จริง (grep `<html>` tag เห็น hashed class) ไม่ใช่ grep literal ชื่อที่ตั้งเอง. — **Why**: ชื่อถูก hash -> grep literal ไม่เจอ -> เกือบรายงาน false-negative ว่าฟอนต์ไม่โหลด.
- **Pattern**: data type อ้าง type ที่ task ก่อนหน้าเป็นเจ้าของ (เช่น `Service.icon: IconName` จาก Icon registry) ให้ import มา constrain แทน re-declare/เดาชื่อ — `tsc --noEmit` พิสูจน์ integrity ข้ามโมดูลฟรี + กัน value ที่ render เป็นกล่องว่าง/ไอคอนหาย. — **Why**: typo ชื่อ icon/enum compile-fail ทันทีแทนพังตอน render; data-only task verify ด้วย `tsc` เป็น gate จริง (count รอง).
- **Pattern**: design.md ที่มีตาราง factor + ตัวอย่างยืนยันตัวเลข -> คำนวณ expected ทุกแถวด้วยมือใส่ test table (รวม 1 ค่าปัดเศษไม่ลงตัวเพื่อพิสูจน์ `Math.round`), อย่าใช้ snapshot. — **Why**: snapshot รับค่าผิดเงียบ; ค่าคำนวณมือ fail ทันทีถ้าสูตรเพี้ยน -> test เป็น executable spec. Export ค่าขอบ (`AGE_MIN/MAX`...) ให้ boundary test reuse แทน hardcode ซ้ำ.
- **Pattern**: vitest โปรเจกต์นี้ไม่อ่าน tsconfig `paths` -> map `resolve.alias["@"]` -> repo root ใน `vitest.config.ts` ตรงๆ (อย่าลง `vite-tsconfig-paths` plugin); `test.environment:"node"` + `include:["app/lib/**/*.test.ts"]` ให้ pure-logic test ไม่ลาก jsdom/Next runtime. — **Why**: import `@/app/...` resolve ไม่ได้ถ้าไม่ map; alias พอ กัน dependency เกิน (ตรง tech.md dependency rule).
- **Pattern**: browser-verify interaction โปรเจกต์นี้ใช้ production build เสมอ — `npm run build` + `PORT=<free> npx next start` แล้วชี้ Playwright ไป `http://127.0.0.1:<port>/` (IPv4 ไม่ใช่ `localhost`). ก่อนเชื่อผลคลิก probe hydration (`__reactFiber$`/`__reactProps$` มีบน element); ไม่มี = ยังไม่ hydrate = คลิก no-op (ไม่ใช่บั๊ก UI). หลังแก้โค้ดทุกครั้ง **rebuild** ก่อนเทสซ้ำ. — **Why**: `next dev` ที่นี่ HMR ws ถูก proxy พัง -> page โหลดแต่ React ไม่ hydrate -> false-negative; `curl -sf ... 200`/build เขียว พิสูจน์แค่ "มีอะไรรันอยู่" ไม่ใช่ "โค้ดล่าสุด" (เคยมี app อื่นจอง :3000 + serve stale `.next`).
- **Pattern**: วัด horizontal overflow ด้วย `document.documentElement.scrollWidth > innerWidth` เป็น primary เสมอ; ค่อยใช้ `getBoundingClientRect().right > innerWidth` ระบุ culprit _หลัง_ ยืนยันมี scroll จริง และ **ตัด svg/rect/circle/path/g ออก** (SVG `preserveAspectRatio="slice"` รายงาน box เกิน viewport เสมอแม้ parent `overflow-hidden` = false positive). culprit เป็น component ของ task อื่น = รายงาน อย่าแก้เงียบ (ยกเว้น task page-wide audit เอง เช่น responsive/a11y — own REQ overflow ทั้งหน้า แก้ได้). culprit probe **ตัด ancestor ที่ clip ออกด้วย** (เดิน parent หา `overflow-x: hidden/clip/auto/scroll` -> เจอ = ignore) รายงานเฉพาะ node "unclipped" — slider/carousel ที่ตั้งใจเลื่อนมี `.right` โต (เช่น 2139px) แต่ถูก clip = ไม่ทำ document overflow จริง. — **Why**: bounding box เดี่ยวไม่ใช่เครื่องมือวัด overflow (false positive จาก SVG geometry + slider clip ทำเกือบไล่แก้ผิดที่); overflow ไม่บอกที่มา เดาแล้วแก้ผิดไฟล์ = scope creep + พัง task boundary (เคสซ้ำ: overflow 768 เป็นของ UtilityBar task 4 ไม่ใช่ section task 5/6).
- **Pattern**: Tailwind `md:` = `min-width:768px` **รวม 768** -> element ที่ตั้งใจ "ซ่อน ≤768px" ด้วย `hidden md:flex` จะ _โผล่_ ที่ 768 พอดี (off-by-one) -> ชน element อื่น = overflow ที่ viewport ขอบ. ซ่อนถึง 768 จริงใช้ `lg:` (≥1024) หรือ `max-md:hidden`. — **Why**: breakpoint inclusive ทำให้ "≤768" กับ "md:" คนละความหมาย; bug class นี้โผล่เฉพาะค่า breakpoint พอดี (ปกติที่ 375/1440) จับได้เฉพาะตอน audit ที่ 768.
- **Pattern**: dropdown/menu open-only — เปิดด้วย hover/focus/click, ปิดด้วย mouseleave/ESC/click-outside เท่านั้น; อย่าให้ `onClick` เป็น toggle เมื่อมี `onMouseEnter`/`onFocus` เปิดอยู่. **กับดักกลับด้าน**: เปิดด้วย `onFocus` + ปิดด้วย ESC ที่คืน focus (`trigger.focus()`) -> focus กลับ trigger `onFocus` เปิดเมนูซ้ำทันที (verify: กด ESC แล้ว `aria-expanded` ยัง `"true"` + `focusRestored:true`). แก้: `suppressOpenRef` (ref boolean): set true ก่อน `trigger.focus()`, ใน `onFocus` ถ้า flag true -> reset+return (ไม่เปิด); tab กลับเข้ามาทีหลังยังเปิดได้. **อ่าน `aria-expanded` แยก call จาก action** (React async re-render) ไม่งั้นเห็น stale พลาดบั๊ก. — **Why**: hover/focus เปิด -> click toggle ปิดทันที (pointer click ฟัง mouseenter ก่อน) -> เมนูไม่เปิด; REQ "ESC คืน focus" ชน "focus เปิดเมนู" โดยตรง — flag คง REQ ทั้งสอง.
- **Pattern**: desktop-nav vs hamburger ที่ขอบ ≤768 split ด้วย `lg:` (≥1024) ไม่ใช่ `md:` — desktop nav `hidden lg:flex`, hamburger `lg:hidden` -> ≤768 (และ tablet ถึง 1023) เห็น hamburger สะอาด ไม่ชน. — **Why**: `md:` = min-width 768 **inclusive** -> nav โผล่ที่ 768 ชน hamburger = overflow (เคสซ้ำ off-by-one). ถ้า design ต้อง full nav ช่วง 769–1023 ค่อยตั้ง custom breakpoint — ยืนยัน intent กับ user ก่อน.
- **Pattern**: filter/grid เก็บ logic เป็น pure fn ใน `lib/` (`filter*(items, ...args)` ไม่มี global) -> state แต่ละ section อิสระเพราะเป็น argument ล้วน, unit test ครอบ filter/search/empty ก่อนแตะ UI. เมื่อ chip filter map 1:1 กับ entity (การ์ด = ประเภทเอง -> กรองเหลือใบเดียว ไร้ค่า) จัด taxonomy เหนือ entity + ยืนยัน completeness ด้วย test (union ของกลุ่ม = ครบทุก entity). — **Why**: ปิด REQ filter/empty ระดับ logic ก่อน wire UI; taxonomy ทำให้ filter มีความหมาย UX จริงแทนทำตาม spec ตรงตัวจนไร้ประโยชน์ — แจ้ง user เป็น assumption เมื่อ taxonomy ไม่ได้มาจาก data.
- **Pattern**: form ที่มี pure validation lib อยู่แล้ว (เช่น calculator -> `lib/premium.ts`) ให้ UI เก็บ raw `string` state จาก `input` แล้ว parse -> `null|number` ตอนคำนวณ แล้วโยนเข้า lib — อย่า duplicate กฎ validation (empty/NaN/นอกช่วง) ใน component; import boundary constants (`AGE_MIN/MAX`...) มาโชว์ใน label/`min`/`max` แทน hardcode. trigger คำนวณที่ submit + blur ฟิลด์สุดท้ายเท่านั้น (ไม่ทุก keystroke) กัน error กระพริบ. blur handler ต้อง guard ว่าทุก field ไม่ว่างก่อน calculate — ไม่งั้น blur ฟิลด์กลางคัน (ฟิลด์อื่นยังว่าง) trigger validation → error ปรากฏทั้งที่ยังกรอกไม่จบ (false-positive UX). — **Why**: validation 2 ที่จะ drift; lib เป็น single source ปิด acceptance ก่อน wire UI, UI แค่ orchestrate. browser-verify ค่าตัวเลข (12,000) แยก action-call (set+submit) กับ read-call ตาม React async re-render.
- **Pattern**: `validateXxx()` คืน `null` เมื่อ valid แต่ tsc ไม่ auto-narrow argument type ผ่าน function call — ถ้า argument เป็น `T | null` + lib return null เมื่อ valid, tsc ยังเห็น `T | null` → TS2345 "not assignable to parameter of type 'T'". แก้: `as T` assertion หลัง guard (safe ถ้า lib contract รับประกัน non-null เมื่อ error=null); หรือ refactor lib ให้ return type predicate (`error is null`). — **Why**: tsc catch bug จริง (ลืมว่า type ยังอาจ null ได้) แต่ lib contract ไม่ได้ encode ใน type — assert บอก intent ชัด, type predicate encode ใน lib signature ถ้าใช้หลายที่.
- **Pattern**: ก่อนใส่สี/สไตล์ state ใหม่ใน component (error/danger/success) grep token ใน `tailwind.config.ts` ก่อน; ไม่มี = เพิ่ม semantic token ที่ config ที่เดียว แล้วเรียกผ่าน utility (`text-danger`) — อย่า hardcode hex ดิบ และอย่าใช้ Tailwind default palette (`text-red-600`) ที่เลี่ยง raw hex แต่ไม่ใช่ token โปรเจกต์. flag ให้ a11y pass ตรวจ contrast ของ token ใหม่. — **Why**: design token เป็น single source (anti-pattern ห้าม hardcode สีดิบ); เพิ่ม token ถูกกว่าตามแก้ค่าซ้ำทีหลัง.
- **Pattern**: section interactive ใหม่ที่ต้องเคารพ `prefers-reduced-motion` (slider/carousel/animation) ใช้ CSS transition ปกติได้เลย — `globals.css` มี media query ครอบ `transition-duration`/`animation` ทั้งหน้าแล้ว ไม่ต้องเขียน `useReducedMotion` hook ต่อ component. slider index แยกเป็น pure fn (`nextSlide/prevSlide` wrap ด้วย modulo) ใน `lib/` -> test wrap-around ใน node env (vitest `environment:node`, include `lib/` เท่านั้น) ก่อนแตะ UI. — **Why**: ได้ REQ-16.5 ฟรีไม่เพิ่ม JS; index math ที่ test แล้วแยกจาก DOM กัน off-by-one/ไม่ wrap โดยไม่ต้อง jsdom.
- **Pattern**: Next 16 `create-next-app` default = **Tailwind v4** (config ผ่าน CSS `@theme`, ไม่มี `tailwind.config.ts`). spec นี้บังคับ tokens ใน `tailwind.config.ts` -> `theme.extend` (REQ-15.1) -> ต้อง pin **Tailwind v3.4** + `postcss`/`autoprefixer`, `globals.css` ใช้ `@tailwind base/components/utilities`. ยืนยัน token compile จริงด้วย grep ใน CSS chunk จริง (`.next/static/**/*.css` — Turbopack วางใต้ `chunks/` ไม่ใช่ `css/`) ไม่ใช่แค่ build เขียว. **กับดัก**: color token emit 2 รูป — บาง utility เป็น hex ดิบ (`#13266b`) แต่ `text-*`/`border-*` ของ Tailwind v3 emit เป็น `rgb(R G B/var(--tw-...-opacity))` (เช่น `#C2293D` -> `rgb(194 41 61/...)`). grep hex อย่างเดียว = false-negative ว่า token ไม่ compile -> grep ทั้งสองรูป (hex และ rgb space-separated). **เพิ่ม**: scaffold ลง repo root ที่มีไฟล์อยู่แล้ว (CLAUDE.md/docs/.claude) ให้เขียน `package.json`+config เองด้วยมือ ไม่ใช่ `create-next-app` — มัน refuse scaffold ลง dir ที่มีไฟล์นอก safelist (นอกจาก default v4 ที่ผิด spec อยู่แล้ว); manual = deterministic + pin version เป๊ะ. ต้องมี root route (`app/page.tsx`) ให้ build เขียว — scaffold task ใช้ temporary design-system preview ที่ "ใช้ทุก token+primitive จริง" บังคับ JIT emit (token grep ทำงาน) แล้ว task assemble แทนทีหลัง. — **Why**: ตาม trend ใช้ v4 จะละเมิด REQ และ semantic utility class ที่ task หลังพึ่งจะไม่ถูก generate; spec เหนือ default ของ tooling. token ใหม่ที่ใช้เฉพาะ `text-/border-` (เช่น `danger`) ไม่โผล่เป็น hex เลย. JIT emit เฉพาะ class ที่ถูกใช้ -> ไม่มี consumer = token หายจาก CSS แม้ config ถูก.
- **Discovery**: `@types/react-dom` เผยแพร่คนละ cadence กับ `react`/`@types/react` — pin `@types/react-dom@<react version>` ตรงๆ ได้ `npm ERR!
