## 📝 AI Diary (REQUIRED - min 150 words)

I assumed task 9 would be a pure pass/fail audit with no code changes — tasks 1–8 had been built
carefully and I expected everything to already be green. That assumption was mostly right but not
entirely: the 768px viewport showed a real 9px overflow. The interesting part was resisting the urge
to guess. lessons.md has a very specific warning that bounding-box `.right` checks produce false
positives from SVG geometry and from intentionally-clipped sliders, so I built the probe to (a) skip
SVG element tags and (b) walk ancestors checking for `overflow-x: hidden/clip/auto/scroll` and
exclude anything clipped. That single discipline paid off immediately: the Testimonials slider items
showed `.right` up to 2139px but all carried `clippedByAncestor: true`, so they were correctly
ignored, and the _only_ unclipped offender was the UtilityBar right group at 777px. Without that
filter I'd have stared at a list of 15 "culprits" and likely chased the slider — the loudest, most
visually obvious number — and broken an intentional behavior.

I was confused for a moment about the hamburger's `aria-expanded: null` reading at 375px, briefly
fearing an a11y gap. Reading Header.tsx showed the hamburger button _does_ set `aria-expanded`; my
selector had matched the hidden desktop `<nav aria-label="เมนูหลัก">` first. A false alarm, caught by
reading source instead of trusting the probe blindly.

I expected the breakpoint fix to be more involved — maybe restructuring flex behavior — but the root
cause was a one-token off-by-one (`md` vs `lg`) where the code's own comment already declared the
correct intent. The cheapest possible fix, and it aligned implementation with documented design.

- **Pattern**: When auditing overflow, the FIRST probe must already exclude SVG tags AND ancestor-clipped subtrees (`overflow-x: hidden/clip/auto/scroll`); report only unclipped offenders. - Avoids chasing intentional sliders and SVG geometry false positives in one shot.
