## 📝 AI Diary (REQUIRED - min 150 words)

I assumed I could compute per-task cost by summing token usage from the session transcript and
multiplying by public prices. I was wrong — repeatedly. My first estimate put task 1 at $16.62;
the ledger later showed tasks run $3-7 each. When I validated my method against task 4's
authoritative $5.36, my deduped transcript sum still said $19.80 — a 3.7x overcount. That was a
humbling, expensive lesson: the transcript is not a billing ledger.

I was confused about why the status line could show `$29.36` when headless `/cost` only printed
"using subscription". The user pushed me to find where the status line gets its number, and that
reframed everything: I read `statusline.sh` and found `.cost.total_cost_usd` arriving in the
payload Claude Code pipes to it. The data was there the whole time; I'd been trying to recompute
something the system already hands over.

I expected my resume-and-scrape tests to "just work," but I botched the same `cd` omission four
times in a row, each time announcing "this time with cd" without actually editing the line. That
is exactly the failure my own rules warn about (error repeats twice → stop). I should have stopped
at the second failure and verified my script by reading it back before running.

## Lessons Learned

- **Pattern**: Read a status line's source script before trying to reproduce its numbers — the system already computed and exposed the value. - Saves reinventing (wrongly) what's handed to you.
- **Discovery**: Per-task cost is only reliable live from `.cost.total_cost_usd`; transcript summation overcounts 1.6-3.7x even deduped. - Capture via a statusline ledger, never recompute from tokens.
