## สิ่งที่ไปได้ดี (What Went Well)

- จับ bug `as-child`/`asChildLink` ปลอมได้เองทันทีหลังเขียน: ทบทวนโค้ดตัวเองก่อน tsc → แก้เป็น styled

  hardcode hex แม้แต่ตัวเดียว → ตรง anti-pattern ของโปรเจกต์, ผ่านโดยไม่ต้องแก้ภายหลัง.
- เลือก `lg:` แทน `md:` สำหรับ Hero split ตั้งแต่แรก (จำบทเรียน off-by-one breakpoint จาก task 4): →
  ลดความเสี่ยง overflow ที่ขอบ 768 ที่ task 9 จะต้องไปไล่จับ.
- phone mockup ทำเป็น UI จำลองจริง (status bar/การ์ด/progress/ปุ่ม) ไม่ใช่กล่องว่าง → ปิด REQ-12.1
  แบบไม่มีข้อกังขา rubric visual completeness.

## สิ่งที่ควรปรับปรุง (What Could Improve)

- เขียน `as-child`/`asChildLink` บน Button ทั้งที่เพิ่งอ่าน Button.tsx เอง — ควร map API ของ primitive
  ในหัวให้ชัดก่อนใช้ ไม่เอา pattern ไลบรารีอื่นมาสวม.
- พลาด HTML semantic 2 จุด (`dt/dd` นอก `dl`, `React.ReactNode` ไม่ import) ในรอบเขียนแรก — งาน markup
  ก็ต้องระวัง validity เท่างาน logic.
- ยังไม่ได้ browser-verify จริง (เพิ่งแค่ build เขียว) — ตาม lessons "build เขียว != โค้ดล่าสุดทำงาน
  บนจอ"; ปล่อยให้ task 9 (responsive/a11y pass) เป็นด่าน verify ภาพจริง.

## อุปสรรคและการแก้ (Blockers & Resolutions)

- **อุปสรรค**: Button ไม่รองรับ asChild/polymorphism แต่ผมเขียนเหมือนรองรับ.
  **การแก้**: เปลี่ยนปุ่ม login เป็น `<Link>` ที่ใส่ class เลียนแบบ variant primary (bg-accent/text-primary
  - state), ลบ import Button ที่ไม่ใช้ออก.
- **อุปสรรค**: `<dt>/<dd>` วางใน `<div>` = invalid HTML.
  **การแก้**: เปลี่ยน wrapper grid เป็น `<dl>`, สลับให้ value เป็น `<dd>` และ label เป็น `<dt>`.
- **อุปสรรค**: ใช้ `React.ReactNode` โดยไม่ได้ import React (strict TS).
  **การแก้**: `import type { ReactNode } from "react"` แล้วเปลี่ยน type เป็น `ReactNode`.
