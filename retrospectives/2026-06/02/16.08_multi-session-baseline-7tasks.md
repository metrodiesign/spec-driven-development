## Lessons Learned

- **Discovery**: multi-session (fresh/task) แพงกว่า all-in-one สำหรับ feature ที่ task พึ่งกันหนัก
  — วัดจริง: 7-session $22.44 vs 1-session $16.16 (~39% แพงกว่า). ต้นทุนจริงของการแยก = re-acquire
  shared context (อ่าน spec + โค้ด task ก่อนใหม่ทุก session = cache-write แพง), ไม่ใช่ prefix tax
  เล็กๆ. cache-read ถูก ~10x → สะสม context ใน 1 session แล้ว reuse ถูกกว่าทิ้ง+สร้างใหม่. แยก
  session ให้ทำเพื่อ **accuracy** (long-context drift, isolate core domain) เป็น conscious trade
  ไม่ใช่ cost optimization. — **Why**: เคยเชื่อกลับด้าน (แยก=ถูกกว่า) ทำให้ default ผิด; โหมด
  all-in-one ใน pane-loop ให้เลือกตาม coupling. (promote แล้วใน lessons.md + memory + spec-tasks skill)
- **Discovery**: cost ของ "multi-session run" = sum ของ ledger แต่ละ impl session (คนละ
  `$CLAUDE_CODE_SESSION_ID`) — ไม่ใช่ ledger ของ orchestration session ที่สั่ง pane-loop. retro
  รวมต้องไล่อ่าน per-task retro/ledger มา sum; session ที่สั่ง orchestrate มี cost แยก (spec+คุย).
  — **Why**: ถ้าอ่าน cost จาก session ที่รัน pane-loop จะได้แค่ค่า orchestration ($11.67) ไม่ใช่
  impl จริง ($22.44) → เทียบผิด.
