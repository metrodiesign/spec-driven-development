## Lessons Learned

- **Pattern**: pure filter fn ที่ task อยู่ก่อน data/ ในลำดับ dependency (data depends filters) ใช้
  generic structural constraint `<T extends {name;tagline;category}>` แทน import concrete data type —
  กัน circular dep, คง type-safe, คืน `T[]` เดิม, test ด้วย fixture ได้โดยไม่ต้องรอ data จริง. owner
  ของ `InsuranceCategory` อยู่ที่ filters (single source) ให้ data/ import มา constrain. — **Why**:
  import `InsuranceType` จาก data/ ใน filters = circular (data ต้อง import category จาก filters);
  generic ตัด cycle และทำให้ task ทดสอบแยกได้จริงตามลำดับ dependency.
- **Pattern**: completeness invariant ("union ทุกหมวด = ทุก entity") ที่ spec บอก "ครอบโดย test ของ
  task ก่อน data" → test ด้วย fixture พิสูจน์ _union logic_ (ไม่ขาด/ไม่ซ้ำ/ไม่มีหมวดว่าง); completeness
  ของ _data จริง_ ปิดด้วย `tsc` ที่ task data (`category: InsuranceCategory` non-optional = compile-time
  guarantee ทุก entity มีหมวด). — **Why**: import data จริงใน test ของ task ก่อนหน้าจะ compile ไม่ผ่าน
  (module ยังไม่มี); แยก "logic invariant (fixture, now)" จาก "data integrity (tsc, later)" ปิดทั้งคู่
  โดยไม่ฝืนลำดับ.
