## Lessons Learned

- **Pattern**: scaffold โปรเจกต์ลงใน repo root ที่มีไฟล์อยู่แล้ว (CLAUDE.md, docs/, .claude/) ให้เขียน `package.json` + config เองด้วยมือ อย่าใช้ `create-next-app` — นอกจาก default Tailwind v4 (ผิด spec) แล้ว create-next-app ยัง refuse scaffold ลง dir ที่มีไฟล์ "แปลก" (ไม่อยู่ใน safelist ของมัน). manual scaffold ปิดทั้งสองปัญหา + คุม pin version เป๊ะ. — **Why**: เสียรอบถ้าลอง create-next-app แล้วมันค้าง/error เพราะ root ไม่ว่าง; manual ให้ deterministic ตรง REQ-20.1 (v3 + token ใน config).
- **Discovery**: `@types/react-dom` version ไม่ lockstep กับ `react`/`@types/react` — เดา `@types/react-dom@19.2.7` ตาม react ได้ `npm ERR! ETARGET No matching version` (จริง = 19.2.3). อย่าเดา @types version จาก runtime package; `npm view @types/<pkg>@latest version` ก่อน pin. — **Why**: install fail รอบแรกเพราะ pin types ตามตัวเลข react; types เผยแพร่คนละ cadence.
- **Pattern**: scaffold task ที่ยังไม่มี test (test มา task หลัง) ตั้ง `passWithNoTests: true` ใน vitest.config เพื่อให้ `npm test` exit 0 ตอน verify task 1 (vitest default exit 1 เมื่อ "No test files found"). — **Why**: task 1 verify สั่ง "vitest รันได้ (0 test ก็ได้)"; ไม่ตั้ง flag = script แดงทั้งที่ตั้งใจไม่มี test.
