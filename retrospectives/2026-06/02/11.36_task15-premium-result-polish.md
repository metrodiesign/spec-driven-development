### Architecture Decisions

- **fade ใช้ `@starting-style` ไม่ใช่ React state+rAF**: REQ-21.3 ระบุ "CSS transition เท่านั้น — ห้าม JS". `@starting-style` = entry transition แบบ zero-JS/zero-keyframe ตรงตัวอักษรของ constraint มากกว่า rAF-class-toggle (ซึ่งเป็น JS). trade-off: รองรับ Chrome 117+ เท่านั้น — ยอมรับได้เพราะ verify บน Chrome prod build.
- **verify @starting-style survival ใน compiled CSS chunk ก่อนเชื่อ**: PostCSS/Tailwind v3 อาจ strip at-rule ไม่รู้จัก -> grep artifact จริงยืนยัน passthrough.

## บันทึก AI (AI Diary)

ผมเริ่มงานนี้คิดว่าจะต้องใช้ React state + `requestAnimationFrame` flip class เพื่อทำ fade-in ตอน result mount เพราะนั่นคือ pattern React ที่ผมคุ้นที่สุด. แต่พออ่าน REQ-21.3 ซ้ำ มันเขียนชัดว่า "CSS transition เท่านั้น (ห้าม @keyframes/JS/dep)". ตรงนี้ผมลังเลจริง — rAF ถือเป็น JS ไหม? ตามตรรกะ rAF แค่ trigger CSS transition ไม่ใช่ animate ค่าเอง น่าจะผ่าน แต่ตัวอักษร constraint บอก "ห้าม JS" ตรงๆ. ผมเลยตัดสินใจเลี่ยงข้อถกเถียงทั้งหมดด้วย `@starting-style` ซึ่งเป็น zero-JS แท้.

ผมสมมติว่า Tailwind v3 + PostgreSQL... ไม่ใช่ — PostCSS อาจ strip `@starting-style` ทิ้งเพราะเป็น at-rule ที่ไม่รู้จัก. ตรงนี้ผมไม่มั่นใจเลย เลยไม่เชื่อแค่ build เขียว — ผม grep compiled CSS chunk จริงหา literal `@starting-style` ก่อน. มันรอด (PostCSS passthrough generic at-rule). ถ้าไม่รอดผมเตรียม fallback ไว้แล้ว.

ผมคาดว่า Button จะยังมี `focus-visible:ring-accent` ฮาร์ดโค้ดให้ต้องลบ (ตาม R2 ใน design) แต่พบว่า task 12 เคลียร์ไปหมดแล้ว — Button base ไม่มี ring เลย ตกไป global `ring-primary`. งานจริงจึงเหลือแค่ result card + verify. ดีที่อ่าน Button.tsx ก่อนแทนเดาจาก design risk note.

## สิ่งที่ไปได้ดี (What Went Well)

- **grep compiled artifact ก่อนเชื่อ @starting-style**: PostCSS อาจ strip at-rule แปลก -> grep chunk เจอ literal -> ยืนยัน passthrough จริง -> ผลกระทบ: ไม่ ship fade ที่เงียบหาย.
- **แยก action call กับ read call ตาม React async**: set+submit ใน call เดียว, อ่าน result/style อีก call -> ได้ค่า 12,000 + computed style ถูกต้อง ไม่ติด race.
- **mouse vs keyboard focus แยกทดสอบจริง**: click ปุ่ม (mouse) -> `focus-visible=false` no ring; Tab เข้าปุ่ม -> `focus-visible=true` ring primary rgb(19,38,107) -> ปิด REQ-21.1 ทั้งสองทิศแบบ objective.

## สิ่งที่ควรปรับปรุง (What Could Improve)

- reduced-motion duration ~0 ผม verify เชิงโครงสร้าง (global `*` media query ครอบ `.result-enter` ด้วยกลไกเดียวกับ transition อื่นทั้งหน้า) ไม่ได้ emulate จริง เพราะ Playwright MCP ไม่มี `emulateMedia` (lessons เดิมรู้อยู่แล้ว). ถ้าจะ rigorous ควรสลับไป chrome-devtools MCP `emulate` ตั้งแต่ต้น — แต่รอบนี้ผมเลือกไม่สลับ tool เพื่อความเร็วเพราะ rule เป็น global ที่ verify มาแล้วหลายรอบ. บันทึก gap ตรงๆ แทนกลบ.

## บทเรียนที่ได้ (Lessons Learned)

- **Pattern**: enter-transition แบบ "ห้าม JS/keyframes/dep" ใช้ CSS `@starting-style` (top-level form, ไม่ใช่ nested — เลี่ยง postcss-nesting) + `transition` บน element; reduced-motion ครอบฟรีโดย global `*` media query เดิม. verify ด้วย grep `@starting-style` ใน `.next/static/chunks/*.css` จริง (PostCSS passthrough at-rule ไม่รู้จัก แต่ต้องยืนยัน ไม่เชื่อแค่ build เขียว). — สำคัญเพราะ rAF/state ถือเป็น JS ผิด constraint; @starting-style เป็น zero-JS แท้ที่หายเงียบได้ถ้า tooling strip.
- **Discovery**: Playwright strict mode reject `nth-of-type` เมื่อ selector แมตช์หลาย element (ฟอร์ม 2 input[type=number]) — ใช้ attribute selector เจาะ (`input[id$="-sum"]`) แทน. — ใช้กับทุก browser-verify ที่มี field ซ้ำชนิดในฟอร์มเดียว.
