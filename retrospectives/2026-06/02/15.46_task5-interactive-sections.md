## Lessons Learned

- **Discovery**: dispatch `new KeyboardEvent('keydown', {key:'Escape', bubbles:true})` บน element ใน
  `browser_evaluate` **trigger React synthetic `onKeyDown` ได้จริง** (React delegate keydown ที่ root) —
  ต่างจาก `mouseenter`/`mouseover` ที่ dispatch มือไม่ถึง React. ดังนั้น verify ESC/keyboard ใช้ dispatched
  keydown ใน eval ได้ (เปิด-ปิด-คืน focus ครบใน 2 call: dispatch แล้วอ่านแยก), แต่ hover/focus-open ยังต้อง
  `page.hover()` (persist ข้าม call). — **Why**: เลี่ยงเสียรอบเดาว่า ESC handler พังทั้งที่ method ถูก;
  รวมกับ lesson เดิม (mouseenter dispatch ไม่ทำงาน) ให้ภาพครบ: keydown=ได้, mouse-enter/over=ไม่ได้.
- **Pattern**: set ค่า React controlled `<select>`/`<input>` ใน eval ต้องใช้ native value setter ของ
  **prototype ที่ตรง tag** (`HTMLSelectElement.prototype` vs `HTMLInputElement.prototype`) แล้ว dispatch
  `input`+`change` — ใช้ผิด prototype setter จะไม่อัปเดต React state. compose หลาย `setIndex`/`setState`
  ใน eval เดียวด้วย functional update (`dots[0].click()` แล้ว `prev.click()` → index สุดท้าย=4) อ่านผลใน
  call ถัดไป. — **Why**: verify controlled form/slider ใน prod build ต้องผ่าน native setter ไม่งั้น state
  ไม่ขยับ = false-negative ว่า component พัง.
