## Lessons Learned

- **Pattern**: guard/regex hook เขียนเสร็จห้ามเชื่อจนกว่าจะผ่าน adversarial test เป็นไฟล์ test suite (ทั้ง bypass case และ false-positive case ด้วยเคสจริง) — รอบแรกของ session นี้ regex ผ่านตา+ผ่านชุด test แรก แต่ reviewer fresh-context เจอ bypass 8 แบบ (indented rm, `/bin/rm`, xargs, `git clean -d -f`, `-nm` combined, `core.hooksPath`) และ false positive ข้ามคำสั่ง (`grep -r && rm -f`) — **Why**: คนเขียน regex ทดสอบเฉพาะเคสที่ตัวเองนึกออก; reviewer ที่สั่งให้ "craft bypass แล้วรันจริง" จับ failure mode ที่ผู้เขียนมองไม่เห็นเสมอ.
- **Discovery**: บทเรียน hook block ฆ่า compound command + hooks มีผลทันทีกลาง session — promote เข้า lessons.md ระหว่าง session แล้ว (commit c2f9a5f) รวม corollary: คำสั่งที่มี destructive string ใน argument (test harness, PR body ที่บรรยาย guard) ต้องส่งผ่านไฟล์ (`bash /tmp/x.sh`, `gh pr create --body-file`) ไม่ inline. — **Why**: โดนซ้ำ 3 ครั้งใน session เดียว (chmod หาย, test harness โดน block, `gh pr create` โดน block).
