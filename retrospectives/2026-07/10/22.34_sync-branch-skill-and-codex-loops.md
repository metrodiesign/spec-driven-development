## Lessons Learned

- **Pattern**: `destructive-guard.sh` block `git commit`/`git push` **ทุกกรณี** ที่ current branch = main/develop โดยไม่สนว่า push จริงทำอะไร (แม้ `git push origin --delete <branch-อื่น>` ก็โดน) — ใช้ `gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>` แทนเมื่อจะลบ remote branch ขณะ checkout อยู่ที่ main/develop (ไม่ใช่ bypass guard, เป็นคนละ code path ที่ guard ไม่จับตั้งแต่ต้น). — **Why**: เคสจริง sync-branch cleanup หลัง PR #65 merge — ลบ remote branch ขณะ HEAD อยู่ develop โดน block ทั้งที่ push ไม่แตะ develop เลย.
- **Pattern**: `git branch -d` เช็ค ancestry กับ upstream ref ที่ผูกไว้ (หรือ HEAD ถ้าไม่มี upstream) — squash commit ไม่มี ancestry กับทั้งคู่ ดังนั้นถ้า upstream ref หายไป (remote ถูกลบก่อนแล้ว/prune/fresh clone) `-d` จะ refuse "not fully merged" ทั้งที่ merge จริงแล้ว (reproduce ยืนยันแล้วด้วย local squash-merge ไม่มี upstream). Fallback เป็น `-D` ปลอดภัยเฉพาะเมื่อ verify merge state แยกต่างหากก่อน (`gh pr view --json state` = MERGED) ไม่ใช่เชื่อผล `-d` อย่างเดียว. — **Why**: squash-merge convention ของ repo นี้ทำให้ pattern นี้เกิดซ้ำได้ทุกครั้งที่ cleanup branch, ยิ่งเสี่ยงถ้า `fetch.prune` เปิดหรือรันข้าม clone.
- **Pattern**: `.claude/workflows/*.js` (Workflow tool script) ใช้ top-level `await`/`return` โดยตั้งใจ (harness ห่อ async function ให้เอง ไม่ใช่ vanilla ES module) — plain `eslint .` parse เป็น syntax error ("return outside of function") ทันที ต้อง exclude directory นี้ใน `eslint.config.mjs` `ignores` ไม่ใช่แก้ syntax ของ script ทิ้ง. — **Why**: workflow script ใหม่ทุกตัวจะพัง CI lint ตั้งแต่ commit แรกจนกว่าจะ exclude — เจอจาก `review-fanout.js` (PR #65).
- **Pattern**: harness ใหม่ที่มี verify/filter/dedup logic (เช่น workflow script) ต้องเช็คกับ `.ai/shared/LESSONS.md` ที่มีอยู่แล้วก่อน ship ไม่ใช่รอรอบ review ถัดไปจับ — เคสจริง: `review-fanout.js` เขียนใหม่ยัง reintroduce pattern เดียวกับบทเรียนบรรทัด 29 ในไฟล์นี้เอง (verifier ที่ตายกลางทางคืน verdict `undefined` แล้วหายเงียบจากทั้ง confirmed/refuted) ทั้งที่บันทึกไว้แล้วในโปรเจกต์เดียวกัน — Codex review รอบถัดมาเป็นคนจับแทน. — **Why**: มี lesson บันทึกไว้ไม่ได้แปลว่าจะถูกนำมาใช้อัตโนมัติตอนเขียนโค้ดใหม่ — ต้อง cross-check เชิงรุกกับ harness ที่มี shape เดียวกัน.
