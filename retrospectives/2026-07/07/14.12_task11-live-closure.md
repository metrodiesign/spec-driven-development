## Lessons Learned

- **Pattern**: gate ที่รันกับ external system จริงตกทั้งที่ FakeAdapter ผ่าน → root-cause ที่ "การสื่อ protocol บน wire" ก่อนเสมอ (request/prompt ไม่เคยบอก vocabulary ที่ verdict ตรวจ) — แก้ที่ translation layer (Ring 2 / adapter prompt), **ห้ามอ่อน verdict**; ตัวพิสูจน์ว่า fix ไม่ทำ gate เสื่อม = discrimination self-test (saboteur ยังตก probe ของตัวเอง) ต้องเขียวก่อน re-run. — **Why**: แรงจูงใจตอน gate แดงคือไปแก้เกณฑ์ (INV-16 violation); เคสจริง P1/P2/P5 ตกเพราะ prompt ไม่บอก echo field/action shape/REQUEST_TOOL — แก้ 2 รอบผ่านหมดโดย verdict ไม่ขยับสักตัว.
- **Pattern**: replay/cache ที่ live gate อ่านได้ ห้าม commit และ default ต้อง per-run — cache ที่ persist ข้าม run/checkout ทำให้ "live" record mint จาก canned response โดยไม่แตะระบบจริง (gate theater + drift canary ตาย). crash-resume convenience ไม่คุ้ม; อยากได้ค่อยเพิ่ม explicit resume flag. — **Why**: เคสจริง Codex P1 — ผม commit `replay/live/conf-*.json` ไปกับ evidence (git add -A) + stable dir, fresh checkout จะได้ all-pass โดย 0 SDK call; ตัว adversarial review ภายในก็เคยเตือน stamped-dir trade-off แล้วผมเลือกผิดข้าง.
- **Pattern**: monitor ที่เฝ้า iTerm pane ด้วย `text of session` ต้อง anchor pattern หลัง marker ล่าสุด (เช่น awk หา occurrence สุดท้ายของ prompt แล้วดูเฉพาะหลังจากนั้น) — scrollback เก็บผลรอบก่อนทั้งหมด, grep ตรงๆ จับผลรอบเก่าแล้วรายงาน done/fail ปลอม; TUI panel ที่เปิดค้าง (เช่น /usage) ก็ render ค่าเก่า — เปิด instance ใหม่ก่อนเชื่อตัวเลข. — **Why**: เคสจริงสองครั้งใน session เดียว: monitor จับ FAIL จาก MODULE_NOT_FOUND เก่าใน scrollback, และ /usage after-capture ได้เลขเท่า before เป๊ะเพราะ panel ค้าง — เกือบบันทึก billing proof ผิด.
