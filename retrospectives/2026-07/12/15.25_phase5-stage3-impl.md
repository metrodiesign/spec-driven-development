## Lessons Learned

- [#slice-tool-verify-not-just-missing-marker] **Discovery**: `scripts/spec-slice.sh` drops a task's mapped `design.md` section SILENTLY (no `MISSING:` marker, no error) when `design.md`'s own "## Requirement Traceability" table uses bare dotted REQ ids (`1.1`, `2.3`) instead of the `REQ-N` prefix the slicer's matcher expects from `tasks.md`'s `Satisfies:` line — a zero-row match never enters the per-row error branch, so nothing prints at all. Hit on every one of 5 tasks in one spec this session. — **Why**: a silently-incomplete context read as complete would drop the design rationale behind an implementation decision with nothing in the tool output hinting anything was missing. — **Classification**: mechanizable
- [#test-not-real-repo-incidental-state] **Pattern**: never write a regression test that asserts a fact about the ACTUAL repository's current content as if it were a behavioral invariant — it passes only until someone uses the feature for real, then breaks CI for a reason unrelated to any bug. Test the code's behavior against a controlled fixture instead. — **Why**: caught by an external review, not self-caught — the test's own passing meant "this feature has never been used," the opposite of what green should signal. — **Classification**: advisory
- [#autobg-notification-not-manual-wait] **Discovery**: a Bash command that auto-backgrounds itself still triggers a normal task-notification on completion — no `ScheduleWakeup`/`Agent` spawn/manual poll needed to "wait" for it, even when the user asked to wait in the foreground. — **Why**: reached for both as ad-hoc waiting mechanisms in the same turn; both were pure waste and had to be cancelled immediately. — **Classification**: advisory
